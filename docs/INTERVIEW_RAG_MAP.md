# Interview RAG map

Implementation notes and evidence pointers, not memorized answers. Paths below
are repository-relative. Measured outcomes are in `evaluation_results/retrieval_v1.json`.

| Interview question | Code / tests / docs | Factual implementation notes |
|---|---|---|
| Why BM25 instead of TF-IDF? | `app/retrieval.py: BM25Index`; tests `test_bm25_frequency_saturation_and_length_normalization`, `test_bm25_formula_and_ties`; `docs/RETRIEVAL_DESIGN.md` | BM25 saturates TF and normalizes by whole-chunk length. Original scorer normalizes only query terms. Implemented as alternative; benchmark tie prevented promotion. |
| What is dense retrieval? | `ExactVectorIndex`; `OpenAIEmbeddingProvider` in `app/materials.py`; `test_vector_mapping_model_filter_and_cosine` | Query/document vectors are compared with cosine; model IDs and dimensions must match. OpenAI adapter is optional; measured offline vectors are token-hash fixtures. |
| Why hybrid retrieval? | `retrieve`, `reciprocal_rank_fusion`; `test_rrf_rank_fusion_deduplicates_and_ignores_score_scale` | Combines lexical and vector candidate sets. Complementarity is a hypothesis; fake-vector results are not semantic evidence. |
| How are scores fused? | `reciprocal_rank_fusion`; `app/retrieval_baseline.py` | RRF sums reciprocal ranks with constant 60. Original weighted 0.45/0.55 fusion remains frozen. Missing branch contributes no score. |
| Why rerank a pool? | `RetrievalConfig`, `CoverageReranker`, `retrieve`; `test_hybrid_rerank_bounded_order_metadata_and_trace` | Depth 12 per branch, fused pool capped at 12, final top-k <=8. Reranker scores only pool texts and cannot recover excluded evidence. |
| Is this a cross-encoder? | `CoverageReranker`; `test_deterministic_local_reranker_phrase_behavior` | No. Deterministic untrained term coverage plus adjacent query-bigram coverage. Protocol allows replacement; no learned reranker is installed or evaluated. |
| What is Recall@k? | `app/retrieval_evaluation.py: metrics`; `test_metrics_known_values_duplicates_and_evidence_required` | Unique judged sources whose anchors are returned, divided by all judged sources. Duplicate chunks cannot inflate recall. |
| What is MRR? | `metrics`; benchmark protocol | Reciprocal rank of first evidence-qualified relevant result; this report truncates at k=3 and averages over queries. Missing evidence contributes zero. |
| What is nDCG? | `metrics`; metric correctness test | Gain 2^grade-1, log2(rank+1) discount, normalize against ideal sorted source grades. Actual chunk positions remain, including duplicate zero-credit hits. |
| How were judgments built? | `benchmarks/retrieval/corpus.json`, `PROTOCOL.md`; `validate_corpus` | 24 authored queries / 12 synthetic lessons, exact anchors, direct=2 and supporting=1. No private data, no independent assessor or held-out split. |
| How did you prevent leakage? | `app/storage.py`; `test_modes_user_book_scope_replacement_deletion_and_rebuild`; existing `tests/test_storage.py` | Store reads/writes keyed by user+book; index constructed from that snapshot. Same book ID across users is tested. Model cannot choose user/book/index paths. |
| How are embeddings cached? | `_cache_chunk_embeddings`; `test_cache_text_model_invalidation_and_no_query_reembedding`, `test_failed_embedding_batch_is_atomic` | Model ID + text SHA-256, batch count/dimension/finite/nonzero validation before mutation. Missing/legacy/changed embeddings are regenerated once. |
| What about deletion races? | `SQLiteStorage.save_material_store`; `test_cache_fill_cannot_resurrect_concurrently_deleted_material`, `test_concurrent_upload_conflict_preserves_winner` | BEGIN IMMEDIATE + expected JSON comparison. Stale cache write rejected; search reloads. Conflicting upload fails explicitly. In-flight reads have snapshot semantics. |
| What happens when embeddings fail? | `search_learning_materials_for_book`, `retrieve`; failure tests | Modern modes retain BM25 fallback; legacy retains original lexical scoring. Error codes logged without private query/content. Valid dense no-match remains empty. |
| What if reranking fails? | `retrieve`; parametrized `test_reranker_failure_preserves_fused_order` | Exceptions, wrong output length or nonfinite scores preserve fused order, mark reranker unused and expose a diagnostic code. |
| How did chunking affect retrieval? | `chunk_text`; `bm25_paragraph` report; `test_chunking_preserves_baseline_and_bounds` | Same 900 cap; paragraph strategy avoids cross-paragraph merging. 12→24 chunks; nDCG fell 0.902186→0.900684, no promotion. |
| Why this vector index? | `ExactVectorIndex`; design document | Standard-library exact scan fits a small local snapshot and avoids orphan sidecars. O(Nd); no claim of ANN latency or large-scale performance. |
| How is attribution preserved? | material chunk metadata; agent tool whitelist; `test_source_mapping_stable_on_order_change` | Every hit retains material ID, source filename, chunk ordinal and text. No page-level PDF coordinates or OCR. |
| What does the agent decide? | `app/agent.py: search_learning_materials`, `TOOLS`; `tests/test_agent.py` | Query/count only; runtime fixes scope. Four existing tools and graph unchanged. State writes stay deterministic backend operations. |
| What did the benchmark show? | `evaluation_results/retrieval_v1.md`; `test_benchmark_reproduces_frozen_baseline_and_committed_metrics` | BM25 tied lexical; hybrid tied old weighted with fake vectors; reranker no quality gain; paragraph slightly worse; fake dense underperformed. |
| Why was the final configuration promoted? | `quality_gate`, `promotion`; gate tests | It was not: incumbent retained. Require >=0.02 nDCG gain without Recall/MRR regression; fake dense ineligible. Negative result is intentional evidence. |
| How is latency measured? | `run_benchmark`; report environment/stages | One warmup + seven repetitions/query, local median/p95; network/SQLite/extraction excluded. Wall-clock observations vary and are not CI assertions. |
| How is agent evaluation different? | `app/evaluation.py`, `evaluation_results/agent_rag_milestone.md` | Eight deterministic graph/tool-routing checks, separate from evidence-ranking metrics. No LLM judge. |
| What are the limitations? | `docs/JOB_SEARCH_RAG_SUMMARY.md`, README | Synthetic authored development corpus, no live semantic measurements or independent judgments, short documents, local identity not auth, no scale claim, Docker daemon unavailable for runtime validation. |
